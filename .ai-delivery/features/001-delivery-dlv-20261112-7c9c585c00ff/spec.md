# 流式翻译产品规格

## 产品目标与边界

本规格将已批准的 INT-001 至 INT-004 转化为可观察、可验收的产品行为：在会议中，将符合覆盖范围的非中文语音自动识别并持续翻译为中文字幕，使需要中文信息的参会者能够在发言进行期间理解内容。

范围限于会议中的语音到中文字幕。Azure 语音实时翻译与 Teams 实时字幕仅为体验参照，不构成集成、品牌或产品一致性要求。中文以外的目标字幕、会议以外的场景，以及与会议平台或翻译服务的集成均不在范围内。

经 PQ-001 接受答案 A，“实时”采用流式语义边界：字幕必须在语音持续输入期间出现并继续更新，不设置固定耗时上限。

## 参与者与权限

- **会议发言人**：在会议中提供语音；其语音仅在属于合格源语言时进入本规格的翻译范围。
- **中文字幕参会者**：查看持续呈现的中文字幕，以理解外语发言。
- 已批准意图未要求角色登录、主持人控制、访问级别或其他权限差异；本规格不新增此类产品行为。参与者可同时具有发言人与字幕查看者身份。

## 用户故事

### US-001 通过流式中文字幕理解外语发言（优先级未指定）

作为需要中文信息的会议参会者，我希望在发言人使用合格源语言发言时，在语音持续输入期间看到自动生成且继续更新的中文字幕，以便在发言进行期间理解其内容。（INT-001、INT-002、INT-003、INT-004、PQ-001）

## 功能需求

- **FR-001**：产品必须接收会议中持续输入的语音，并对其中的合格源语言语音提供翻译处理。（INT-002、INT-003）
- **FR-002**：产品必须自动检测待翻译语音所使用的合格源语言，不要求参会者预先手动选择源语言。（INT-004）
- **FR-003**：产品必须将识别出的合格源语言语音内容翻译为中文，并以字幕形式呈现。（INT-001、INT-002、INT-004）
- **FR-004**：产品必须随着会议语音持续输入而出现字幕并连续提供字幕更新，不得仅在整段会议语音全部结束后一次性提供翻译结果；该流式语义边界不设置固定耗时上限。（INT-003、PQ-001）
- **FR-005**：产品必须覆盖业务所采用翻译能力能够自动检测且能够翻译为中文的全部非中文源语言；不满足这两个条件的语言不属于合格源语言。（INT-002、INT-004）
- **FR-006**：当某段输入无法被检测为合格源语言、无法识别或无法翻译时，不得将该段输入计为成功翻译；后续再次出现可处理的合格源语言语音时，产品必须能够继续执行 FR-002 至 FR-004。（INT-001、INT-003；最小行为闭合）

## 产品质量要求

INT-001 与 INT-003 要求字幕“及时”和“实时”；PQ-001 已接受流式语义边界，并明确不设置固定耗时上限，因此该要求由 FR-004 的可观察先后关系验收，不创建 NFR 或数值门禁。除已批准的流式产品行为外，当前没有获批准的额外性能、可靠性、安全、隐私、可访问性或合规产品质量要求。

## 领域术语

- **合格源语言**：在产品被验收时，业务所采用翻译能力同时支持自动检测并翻译为中文的非中文语言。
- **中文字幕**：以中文文字呈现、表达对应源语音内容的翻译结果。
- **流式字幕**：在语音持续输入期间连续产生字幕更新，而不是等待整段会议语音全部结束后一次性产生结果。
- **语音输入段**：一段可被观察并判断是否完成检测、识别和翻译的会议语音；该术语只用于描述产品行为，不规定技术切分方式。
- **成功翻译**：源语言被自动检测为合格源语言，且对应语音内容以中文字幕呈现。

## 前置条件与触发条件

- **前置条件**：会议正在进行；发言人的语音能够作为连续输入被产品接收；待验证语言属于验收时确定的合格源语言集合。
- **触发条件**：发言人开始提供非中文语音。
- 中文语音、不属于合格源语言的语音、无语音输入和多个发言人同时发言的处理结果均未由已批准意图规定，不作为成功翻译承诺。

## 行为模型

### US-001 通过流式中文字幕理解外语发言

- **正常路径**：发言人使用合格源语言持续发言；产品自动检测语言，识别并翻译内容，在语音持续输入期间连续呈现中文字幕。（FR-001 至 FR-005；AC-001 至 AC-004）
- **替代路径**：不同会议分别使用合格源语言集合中的不同语言时，参会者无需预选语言，均能获得中文字幕。（FR-002、FR-005；AC-002）
- **边界路径**：源语言必须同时满足“非中文”“可自动检测”“可翻译为中文”；缺少任一条件即不属于本规格承诺的源语言范围。（FR-005；AC-002）
- **错误路径**：某段输入无法完成检测、识别或翻译时，该段不满足成功翻译标准，不得作为通过证据。（FR-006；AC-005）
- **恢复路径**：错误输入之后再次提供可处理的合格源语言语音时，产品恢复正常的自动检测、翻译与流式字幕行为。（FR-006；AC-005）
- **实时边界**：字幕在语音持续输入期间出现并继续更新即可满足已接受的流式语义边界；不采用固定耗时上限。（FR-004；AC-004；PQ-001）

## 业务状态、业务数据规则与不变量

可观察的业务状态依次为：

1. **等待语音**：尚无待处理的语音输入。
2. **接收语音**：会议语音正在持续输入。
3. **呈现字幕**：合格源语言内容已产生中文字幕，且可随后续语音继续更新。
4. **当前输入不可翻译**：当前输入未能形成成功翻译；后续合格输入仍可重新进入接收语音与呈现字幕状态。

业务规则与不变量：

- 成功翻译的目标语言始终为中文，呈现形式始终为字幕。
- 源语言范围由“可自动检测”与“可翻译为中文”两个条件共同确定，并排除中文。
- 源语言检测是自动行为，不以用户预选语言为前置条件。
- 一次不可翻译的输入不得把后续合格输入永久排除在翻译流程之外。
- 翻译服务能力范围的变化会改变合格源语言集合，但不得改变上述集合判定规则。

## 错误与恢复行为

- 无法检测语言、无法识别语音或无法翻译为中文的输入不满足成功翻译定义，也不能作为相关 AC 或 IQA 的通过结果。
- 已批准意图未规定错误提示的文字、形式或展示时机，本规格不新增错误提示要求。
- 当前输入失败后，后续合格源语言输入必须仍可产生中文字幕；恢复仅以用户可观察的后续正常翻译为准，不规定恢复机制。
- 对不合格源语言、中文、静音或重叠发言的特定输出未获批准，不据此判定产品失败；但任何此类输出均不得被用来证明合格源语言的验收通过。

## 安全、隐私与可访问性行为

当前没有由已批准 Intent 或 Constitution 的准确产品条款触发的额外用户可见安全、隐私或可访问性要求。Constitution 中关于凭据、输入验证、least privilege、secret 与客户内容日志的条款属于后续技术实现治理，不在本规格中转化为未经批准的产品行为或验收义务。

## 性能、可靠性与其他质量边界

- 流式而非整段会议结束后批量输出是已批准的产品行为，见 FR-004。
- INT-001 与 INT-003 的实时性通过边界已由 PQ-001 确定为流式语义边界：字幕在语音持续输入期间出现并继续更新，不设置固定耗时上限。
- 当前没有获批准的可用率、恢复时限、翻译准确率数值、并发规模、正式可访问性等级或其他质量目标，不创建相应门禁。

## 成功标准

- **SC-001**：对于任一合格源语言的会议语音，参会者无需预选源语言即可看到表达该语音内容的中文字幕。（INT-001、INT-002、INT-004）
- **SC-002**：对于持续的合格源语言语音，字幕在语音持续输入期间、整段会议语音结束前产生并可继续更新，而不是仅在全部输入结束后一次性出现；是否通过不采用固定耗时上限。（INT-003、PQ-001）
- **SC-003**：发生一段不可翻译输入后，后续可处理的合格源语言语音仍能再次产生符合 SC-001 与 SC-002 的字幕。（INT-001、INT-003；最小行为闭合）

SC-002 以 PQ-001 接受的流式语义边界判定“及时/实时”，不附加固定耗时上限。

## 验收场景

### IQA-001 单一合格源语言的自动检测与中文字幕

- **追踪：** INT-001、INT-002、INT-004 / US-001 / FR-001、FR-002、FR-003 / AC-001、AC-003
- **前置条件：** 会议正在进行；输入为一种合格源语言的清晰、可识别语音；未预选源语言。
- **操作：** 持续提供具有可核对含义的源语言会议语音并观察字幕。
- **预期结果：** 产品自动检测源语言，并以中文字幕呈现与语音内容对应的信息。
- **必需证据：** 可关联的源语音、自动检测结果与实际字幕记录，以及对预期含义和实际字幕是否对应的判定。

### IQA-002 合格源语言范围覆盖

- **追踪：** INT-002、INT-004 / US-001 / FR-002、FR-003、FR-005 / AC-002、AC-003
- **前置条件：** 已取得验收时业务所采用翻译能力可自动检测且可翻译为中文的非中文语言完整清单。
- **操作：** 对清单中的每种语言分别执行 IQA-001。
- **预期结果：** 清单中的每种语言均通过自动检测与中文字幕验收；没有语言因要求用户预选而被计为通过。
- **必需证据：** 带确定时点的完整语言清单，以及每种语言与对应 IQA-001 结果的逐项映射。

### IQA-003 持续语音的流式字幕

- **追踪：** INT-001、INT-003、PQ-001 / US-001 / FR-001、FR-003、FR-004 / AC-001、AC-004
- **前置条件：** 持续提供足以观察多次字幕更新的合格源语言会议语音。
- **操作：** 在语音输入持续期间观察字幕，并继续输入后续可翻译内容。
- **预期结果：** 在语音持续输入期间、整段输入结束前已出现中文字幕，后续内容使字幕继续更新；结果不是在全部输入结束后才一次性出现，且不以固定耗时上限判定。
- **必需证据：** 能够比较语音输入进程、首次字幕呈现、后续字幕更新与输入结束先后关系的记录。

### IQA-004 不可翻译输入后的恢复

- **追踪：** INT-001、INT-003 / US-001 / FR-006 / AC-005
- **前置条件：** 先提供一段无法完成成功翻译的输入，随后提供清晰、可处理的合格源语言语音。
- **操作：** 观察首段输入结果，再持续提供后一段语音。
- **预期结果：** 首段不被计为成功翻译；后一段重新产生自动检测、中文翻译与流式字幕结果。
- **必需证据：** 两段输入及其顺序、首段未成功的判定，以及后一段符合 IQA-001 与 IQA-003 预期结果的记录。

## 验收标准

- **AC-001**：输入可处理的合格源语言会议语音后，参会者看到与语音内容对应的中文字幕。
- **AC-002**：验收时合格源语言完整清单中的每种语言均可被自动检测并翻译为中文，无需用户预选源语言。
- **AC-003**：成功结果的目标语言为中文，呈现形式为字幕。
- **AC-004**：持续输入合格源语言语音时，字幕在语音持续输入期间、整段输入结束前出现，且能够随随后输入继续更新；仅在全部输入结束后一次性输出判定为失败，不设置固定耗时上限。
- **AC-005**：一段不可翻译输入不计为成功；其后的可处理合格源语言语音能够再次满足 AC-001 与 AC-004。

## 测试策略

### 开发者验证

- 验证自动语言检测、中文目标字幕、持续更新和错误后恢复的产品行为，为 Independent QA 提供可重复执行的候选结果。
- 开发者验证覆盖 FR-001 至 FR-006，但其结果只作为辅助证据，不替代 IQA-001 至 IQA-004。
- 如产品行为依赖外部翻译能力，离线替代结果不得作为实际语言覆盖、翻译或端到端行为已通过的证据。

### Independent QA 验收

- 针对待验收的同一候选产品独立执行 IQA-001 至 IQA-004。
- IQA-002 必须以验收时业务所采用翻译能力的完整合格源语言清单为范围，逐项保留结果；抽取部分语言不能证明 INT-002 与 INT-004 全部通过。
- 依赖外部翻译能力的验收必须使用真实测试服务完成相关 contract、integration、functional 与 end-to-end 路径；Mock、单元测试、构建成功或页面加载不能替代用户可见的翻译与字幕证据。
- Independent QA 必须按 PQ-001 已接受的流式语义边界执行 IQA-003，不得使用未获批准的延迟数字或人工门禁。

### 总体通过与失败标准

- **通过**：AC-001 至 AC-005 均由对应 IQA 场景的必需证据证明通过；IQA-002 覆盖完整合格源语言集合；IQA-003 按 PQ-001 接受的流式语义边界通过；没有场景依赖 Mock 替代用户可见结果。
- **失败**：任一 AC 未通过或缺少必需证据、任一合格源语言未通过 IQA-002、字幕仅在全部输入结束后一次性出现，或错误后无法处理后续合格输入。
- 不适用的范围外输入不单独导致失败，但不得用于替代任何范围内验收。

## 假设、依赖与范围外边界

- **假设**：同一参与者可同时发言和查看字幕；该表达细节不改变任何产品义务。
- **假设**：“整段会议语音”指本次连续验收输入的全部内容，而非规定技术会话或切分方式。
