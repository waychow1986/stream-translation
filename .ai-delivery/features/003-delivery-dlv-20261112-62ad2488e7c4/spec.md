# 流式语音翻译产品规格

## 产品目标与边界

本规格将已批准的 **INT-001** 至 **INT-005** 转化为可观察、可验收的产品行为：在会议外语发言持续进行时，自动识别输入语音所使用的语言，将可识别的外语语音转换为中文文字，并以流式字幕持续提供给需要中文理解发言的会议参与者。

范围限于会议中的外语语音到中文字幕。除会议外的场景、中文以外的目标语言、现有业务系统改造，以及语言识别能力不能识别的输入语言均不在已批准承诺内。业务优先级仍未指定。

## 参与者与权限

- **外语发言人**：在会议中产生待识别和翻译的外语语音；无需预先声明所使用的语言。
- **中文会议参与者**：在外语发言期间查看持续产生的中文字幕，以理解发言内容。
- **语言识别能力**：作为业务依赖，判定输入语音所使用的语言；其可识别范围界定本次能力可处理的输入边界。
- 已批准 Intent 未规定账户、角色分级、管理操作或参与者之间的差异化权限，因此本规格不新增此类权限行为。

## 用户故事

### US-001 在外语发言期间阅读中文字幕（优先级未指定）

作为需要用中文理解外语发言的会议参与者，我希望在发言持续进行时看到按发言进展持续提供的中文文字，以便及时理解发言并参与会议。（**INT-001、INT-002、INT-004、INT-005**）

### US-002 无需预设输入语言即可获得翻译（优先级未指定）

作为会议参与者，我希望系统自动识别发言所使用的语言，而无需我预先指定，以便不同外语发言进入时仍可获得中文字幕。（**INT-003**）

## 功能需求

- **FR-001**：产品必须接收会议中持续产生的语音内容作为识别与翻译输入。（**INT-002、INT-004**）
- **FR-002**：产品必须通过已批准的语言识别能力自动检测输入语音所使用的语言，不要求会议参与者预先选择或声明输入语言。（**INT-003**）
- **FR-003**：对于语言识别能力能够识别的外语语音，产品必须将其已识别文字内容翻译为中文文字。（**INT-002、INT-003、INT-005**）
- **FR-004**：产品必须在外语发言仍在进行时，随着新的可翻译内容产生而依次提供中文字幕，不得以整段发言结束作为首次输出的必要条件。（**INT-001、INT-004**）
- **FR-005**：当一段输入暂时没有可识别、可翻译的语音内容，而后再次出现可识别内容时，产品必须继续对后续内容执行自动识别、翻译和流式字幕输出。（**INT-001、INT-003、INT-004**）

## 产品质量要求

“及时”和“实时”的获批含义仅闭合为 **FR-004** 所述的用户可见流式行为：字幕在发言进行期间开始并随可翻译内容继续产生。当前没有获批准的额外延迟数值、吞吐量、准确率、可用率、恢复时限、安全等级、隐私等级、可访问性等级或其他产品质量要求，因此不创建 NFR。

## 领域术语

- **输入语音**：会议中发言人持续产生、供语言识别与翻译的语音内容。
- **语言识别**：无需参与者预先指定语言，由已批准的语言识别能力判断输入语音所使用语言的业务能力。
- **可识别外语语音**：位于语言识别能力覆盖范围内，并具有足够可识别内容的非中文输入语音。
- **可翻译内容**：已完成必要语言识别和文字识别、能够形成中文翻译的输入内容。
- **中文字幕**：以中文文字表达输入发言含义并按发言进展提供的输出。
- **流式字幕**：在发言结束前开始，并随着后续可翻译内容依次继续产生的中文字幕；该术语不承诺未经批准的固定刷新周期或延迟数值。

## 前置条件与触发条件

- 前置条件：会议中存在待处理的语音输入；输入语言位于语言识别能力可识别的范围内，才适用成功翻译承诺。
- 触发条件：外语发言人产生可识别语音内容。
- 不要求参与者在触发前选择、声明或确认输入语言。

## 行为模型

### US-001 外语发言期间的流式字幕

1. 外语发言人开始产生会议语音，产品接收持续输入（**FR-001**）。
2. 产品自动确定输入语音所使用的语言（**FR-002**）。
3. 产品把可翻译内容转换为中文文字（**FR-003**）。
4. 在发言仍在进行时，产品提供首批中文字幕；后续出现新的可翻译内容时，继续按输入先后提供字幕（**FR-004、AC-002、AC-003**）。
5. 中文会议参与者可在发言过程中阅读这些字幕。

替代与边界路径：

- 若语言识别能力不能识别输入语言，则该输入超出已批准服务范围，不承诺生成翻译字幕。
- 若当前输入暂时没有可识别、可翻译的内容，则不会凭空形成该段输入的翻译；后续再次出现可识别内容时按正常路径继续（**FR-005、AC-004**）。
- 字幕分段、排版和既有字幕修订方式未被批准，不改变“发言期间开始并随新内容继续产生”的验收边界。

### US-002 自动识别输入语言

1. 参与者不选择或声明输入语言。
2. 外语发言进入后，产品使用语言识别能力确定其语言（**FR-002**）。
3. 对可识别外语语音，产品继续生成中文流式字幕（**FR-003、FR-004、AC-001**）。

## 业务状态、业务数据规则与不变量

业务状态按单次持续语音输入的可观察进展描述：

1. **等待可识别内容**：尚无能够形成翻译的语音内容。
2. **语言已识别**：输入语言已由语言识别能力确定。
3. **字幕产生中**：已有可翻译内容，中文字幕在发言期间开始并随新内容继续产生。
4. 当输入暂时不可识别时回到**等待可识别内容**；出现后续可识别内容后可再次进入**语言已识别**和**字幕产生中**。

不变量：

- 目标字幕语言始终为中文（**INT-005**）。
- 输入语言由语言识别能力自动判断，不要求参与者预设（**INT-003**）。
- 字幕顺序必须保持对应可翻译输入内容的先后关系，避免“持续提供”在用户侧变得不可理解（**INT-001、INT-004** 的最小行为闭合）。
- 输入语言超出语言识别覆盖范围时，不属于成功翻译承诺。

本规格只要求验收所需的语音内容、识别语言和中文字幕之间具有可观察对应关系；未批准额外的保存期限、导出、历史记录、说话人身份或字幕格式规则。

## 错误与恢复行为

- 输入语言无法被语言识别能力识别时，该输入处于已声明的范围边界；当前没有获批准的错误提示、人工选择语言或替代翻译行为。
- 暂时没有可识别内容时，不要求生成该段字幕；后续可识别语音出现后必须恢复正常的自动识别、翻译和流式输出，无需参与者预设语言（**FR-005**）。
- 当前没有获批准的外部服务故障提示、重试次数、超时或恢复时限要求，不在本规格中新增这些产品行为。

## 安全、隐私与可访问性行为

已批准 Intent 未提出安全、隐私或可访问性产品行为；Constitution 的相关条款为后续实现治理约束，未直接批准额外的用户可见产品能力。因此当前没有获批准的额外产品要求。

## 性能、可靠性与其他质量边界

除 **FR-004** 的流式行为外，当前没有获批准的性能数值、可靠性目标或其他质量目标。“实时”不被解释为未经批准的数值门槛。语言识别覆盖范围是业务依赖边界，而非本规格新增的可靠性承诺。

## 成功标准

- **SC-001**：对于语言识别能力可识别的会议外语语音，参与者能够在发言仍在进行时开始看到中文文字，并在后续可翻译内容出现时继续看到对应字幕。（**INT-001、INT-002、INT-004、INT-005**）
- **SC-002**：在参与者未预先指定输入语言的情况下，可识别外语语音仍被自动识别并产生中文字幕。（**INT-003**）
- **SC-003**：暂时没有可识别内容后再次出现可识别外语语音时，中文字幕处理能够继续，且无需参与者补充语言选择。（**INT-001、INT-003、INT-004**）

## 验收场景

### IQA-001 外语发言期间持续产生中文字幕

- **追踪：** INT-001 / INT-002 / INT-004 / INT-005 / US-001 / FR-001 / FR-003 / FR-004 / AC-002 / AC-003
- **前置条件：** 存在一段语言识别能力可识别、包含连续可翻译内容的会议外语语音。
- **操作：** 提供该语音并在发言进行期间观察中文字幕，随后继续提供新的可翻译内容。
- **预期结果：** 发言结束前出现与已处理内容对应的中文文字；后续内容出现后，按输入先后继续产生中文字幕。
- **必需证据：** 可关联的输入语音进展、发言结束边界、每次可观察字幕结果及其顺序，足以判定字幕是否在发言结束前开始并随内容继续产生。

### IQA-002 未预设语言时自动识别并翻译

- **追踪：** INT-002 / INT-003 / INT-005 / US-002 / FR-002 / FR-003 / AC-001 / AC-002
- **前置条件：** 未选择或声明输入语言；存在一段语言识别能力可识别的会议外语语音。
- **操作：** 直接提供该外语语音并观察语言识别与字幕结果。
- **预期结果：** 无需参与者补充输入语言，语音语言被自动识别，并产生对应的中文文字。
- **必需证据：** 未预设输入语言的记录、语言识别结果、输入内容与中文字幕的可观察对应结果。

### IQA-003 暂时无可识别内容后的继续处理

- **追踪：** INT-001 / INT-003 / INT-004 / US-001 / FR-005 / AC-004
- **前置条件：** 存在由可识别外语语音、暂时无可识别内容、后续可识别外语语音依次组成的会议输入。
- **操作：** 按上述顺序持续提供输入，不预设输入语言。
- **预期结果：** 产品不为无可识别内容凭空形成翻译；后续可识别语音出现后，自动识别、翻译及流式字幕继续工作。
- **必需证据：** 三个输入阶段及其对应输出记录，足以判定中间阶段未产生虚构翻译、后续阶段恢复字幕处理。

## 验收标准

- **AC-001**：无需参与者预先指定输入语言，产品能够自动确定可识别外语语音所使用的语言。（**INT-003**）
- **AC-002**：语言识别能力可识别的外语语音产生含义对应的中文文字，而非其他目标语言文字。（**INT-002、INT-005**）
- **AC-003**：中文字幕在发言结束前开始出现，并在新的可翻译内容产生后按输入先后继续提供。（**INT-001、INT-004**）
- **AC-004**：暂时没有可识别内容后再次出现可识别外语语音时，无需参与者预设语言即可继续产生对应的中文流式字幕。（**INT-001、INT-003、INT-004**）

## 测试策略

### 开发者验证

- 独立验证每项可观察能力：自动语言识别、外语语音到中文文字的转换、发言结束前出现字幕、后续内容的顺序输出，以及暂时无可识别内容后的继续处理。
- 使用能够明确区分输入阶段、发言结束边界和字幕输出顺序的代表性语音场景，按 **AC-001** 至 **AC-004** 给出逐项通过或失败结果。
- 开发者验证可提供辅助证据，但不能替代 Independent QA 对用户可见完整行为的验收。

### Independent QA 验收

- 独立执行 **IQA-001** 至 **IQA-003**。因已批准行为依赖外部语言识别能力，应依据 Constitution“外部 integration 必须针对真实测试服务执行 contract、integration 和 end-to-end 测试”，使用真实测试服务验证依赖交互及端到端用户结果；Mock 结果不得作为功能验收通过证据。
- 对每个场景保存其“必需证据”，并逐项判定所追踪的 AC。测试语音仅需位于已批准语言识别能力的可识别范围内，不据此扩张为固定语言清单或覆盖率目标。

### 总体通过与失败标准

- **通过**：**IQA-001** 至 **IQA-003** 均取得所列必需证据，且 **AC-001** 至 **AC-004** 全部满足；端到端用户可见结果来自真实测试服务。
- **失败**：任一 IQA 无法执行、缺少必需证据、任一 AC 不满足，或仅有 Mock、单元检查、构建、健康检查等辅助结果而没有真实端到端用户结果。
- 未获批准的延迟数值、准确率、语言覆盖数量及其他质量指标不得作为额外通过或失败条件。

## 假设、依赖与范围外边界

### 假设

- “中文字幕”按普通含义指中文文字形式；简体或繁体、排版和分段未获指定，不作为验收差异。
- “持续提供”按输入内容的时间先后理解；具体字幕单元大小和既有字幕是否修订未获指定，不作为额外产品要求。
- 单次会议输入中允许短暂无可识别内容；将其视为持续输入中的等待状态，而非新增的会话控制能力。

### 依赖

- 输入语言识别依赖已批准 Intent 指定的 Azure AI Foundry 语音转文本服务语言识别能力。
- 可服务输入范围受该语言识别能力实际覆盖范围约束。

### 范围外边界

- 会议以外的使用场景。
- 中文以外的目标字幕语言。
- 对现有业务系统的改造或集成。
- 为超出语言识别覆盖范围的输入提供翻译。
- 账户、角色、管理、字幕保存与导出、历史记录、说话人身份、人工指定语言、错误提示或替代翻译能力。
- 未获批准的性能、可靠性、安全、隐私、可访问性、合规数值或等级目标。
